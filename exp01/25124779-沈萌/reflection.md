## 一、理解实验本质
把5000条英文评论切成一万多个词，然后让程序通过调整参数，即窗口的大小window-2/window-5，根据这个词临近的2/5个词去猜这个词的方式反复训练，最后每个词都在一个128维的空间里获得一个固定位置，再通过计算余弦相似度，查到每个词最接近的五个词。

## 二、理解代码
根据老师提供的代码对run_lab.py进行了理解和优化，main.py则将用到的所有代码进行了整合，形成了分为四段的核心代码，对于这四段代码的具体理解如下：
### 第 1 段：预处理：分词
首先对数据进行预处理，计算机看不懂句子，只认识"词"。所以第一步要把
"This phone has a good screen" 切成 ["this", "phone", "has", "a", "good", "screen"]。

```python
TOKEN_PATTERN = re.compile(r"[a-z]+(?:'[a-z]+)?|[0-9]+")
```
预处理是"清理"而不是"删减"：反转义、去 HTML 标签、转小写、切词，但不删停用词。
因此这里连续的英文字母都算作一个词；带撇号的（don't）算一个词（从而保留否定含义）；数字也算一个词。
### 第 2 段：训练
```python
model = Word2Vec(window=window, **FIXED)
model.build_vocab(corpus)
model.train(corpus, total_examples=model.corpus_count, epochs=EPOCHS)
```
Word2Vec的本质就是不停地把一个词遮住，让模型用左右的词去猜它；猜错就调整这个词的位置，猜对也微调，直到确定位置，即128维向量。
Window则决定了通过这个词的左右几个词去猜：
- window=2：只看紧挨着的两个词 → 学到的是“什么词能填进这个语法位置”；
- window=5：看得更远 → 会把同一段话里的其他词也当成线索，虽然可以看的更完整，但是也容易出现噪声。
### 第 3 段：计算余弦
```python
kv.similarity("good", "bad")
```
通过余弦公式计算两个词向量之间的夹角大小。只看夹角大小，不看向量的模长，因为模长体现的是词频，但是看不出两个词向量之间的关系。
### 第 4 段：找Top-5
```python
kv.most_similar("battery", topn=5)
```
把这个词跟词表里另外 11,323 个词各算一次夹角，按"夹角从小到大"排个序，取前 5 个。

## 三、个人收获
### 1.相似不等于同义
实验中最有代表型的结果就是：good和bad的余弦是0.747，比good与great之间的余弦还略高一些。这让我意识到，在模型学里，“相似度高”不完全意味着“意思接近”，而是词与词之间的可替代性，它看不出来good是褒义、bad是贬义，但是它们都是形容词，一般我们会说`very good/bad`，但我们很少说`very great`
### 2.数字高不代表可信
实验中还有一个异常结果就是：delivery的Top-5是cecelia、91737这种完全不相关的词，可余弦相似度均在0.94以上。原因就在于delivery只出现了20 次，相当于这个输入向量只能被更新20次，相对于128维的参数空间，这点更新量几乎不足以让向量离开随机初始化的位置。因此，以后评估近邻结果时必须同时检查词频是否充足。
### 3.“受控实验”对于其他变量的要求是很严格的
除了window大小，维度、轮数、最小词频、随机种子，连Python的哈希种子都要固定，否则同样的参数跑两次结果都可能不一样。
### 4.应用广泛
在体验了词向量的表述与相似度分析后，我学会了如何去用向量表述一个词，并且如何用余弦来计算词与词之间的关系。其最直接的用途就是实验二的情感分类：要求导出的embedding.npy就是神经网络的输入层，每个词对应一个128维向量，模型可以在这个基础上学习不同的情感表示。
进一步，还可以应用到语义检索与 RAG：把句子或文档变成向量，用户提问时先算相似度召回候选，再交给大模型回答，其他同学做的“上大知讯”当中也同样运用了这样的思路做了RAG；在做数据治理时，也可以用于文本清洗和同义词发现：用近邻可以自动发现同一件商品的不同叫法、拼写变体，甚至发现数据里的噪声从而清除。

但这次实验也让我记住了三个前提：词频要够、词表要覆盖、领域要对得上。换一个领域（比如医疗、法律），这套向量基本要重训，不能直接搬。

## 四、个人反思
### 1.语料规模大小的重要性
我们只抓取了5000条评论，结果导致具体的商品名几乎没被区分开，比如phone的近邻居然是grill。后续我们会尝试扩大语料数量，或者通过选取同一品类的评论，让聚焦的领域更集中，规避数据不足导致的噪声。
### 2.理解比跑通代码更重要
在AI的加持下，把脚本跑出结果变得非常容易，但要说清“为什么good和bad这么像”“为什么窗口变大后price的近邻从size变成printer”，需要回到语料里一句一句找证据，也需要对程序的底层逻辑理解透彻。
### 3.可以将异常分析自动化
可以将异常分析写成固定脚本，而不是每次手工翻CSV，但是也要评估效果。
