核心方法
KMeans 聚类 · 关联分析（Apriori）
功能
望月
- 真实月相：按朔望月周期（29.530588853 天）推算当日月相，
以已知新月 2000-01-06 18:14 UTC 为基准，用椭圆路径绘制盈亏
- 睡前打卡：点「我睡了」记录入睡，点「我醒了」记录醒来，自动计算时长
- 昼夜切换：白天为浅蓝天空与太阳，夜间为深空与月亮，三个页面共用同一判定
- 天气：长按月亮 / 太阳，可在晴天与雨天之间切换；雨天有云雨与月亮隐现
- 晚睡追问：入睡时间晚于用户设定的标准时，弹出原因选择
（学业压力、工作压力、赶 deadline、刷手机、追剧、情感、情绪、
身体不适、环境、睡不着、说不清）
- 异常保护：忘记点「我醒了」导致时长超过 16 小时时，不直接写入，
而是让用户选择「按 8 小时补上 / 手动填时间 / 丢弃这一晚」
星图
- 月历热力：每晚一颗星。大小表示睡眠时长，颜色由
「实际入睡时间与用户设定的早睡标准之差」插值得到——早为暖金，晚为冷蓝
- 四项统计：平均入睡、平均苏醒、平均睡眠、本月早睡天数
- 补录与修改：长按空白格补录那一晚；长按有记录的格修改或删除
- ✦ 星河：把当月所有夜晚按日期连成一条曲线，分三阶段动画——
日历排布 → 金线依次连接 → 收束成一条星河，支持点击下流星
枕边
- 夜相：对最近若干晚做 KMeans 聚类，给出六种类型之一，
并展示平均入睡、平均时长、规律度
（晨光型 / 节律型 / 轻眠型 / 潮汐型 / 夜航型 / 报复性夜猫）
- 星语：每天写一句话，按心情着色，挂成一条藤蔓。
支持左右拖动看更早的夜；写的时候可以改日期，补写以前的夜晚；
长按某一句可修改或删除
- 周报：按自然周生成（记满 4 晚才寄出），进入页面时会自动补齐所有历史周，
其中只有最近一封为未读。内容含 7 项指标、节律分、与上一周的对比、
最晚的一夜、一句可执行的建议。信封堆叠展示，点开有开信动画
- 使用说明：集中列出所有隐藏操作（长按换天气、长按格子补录、长按句子修改等）

数据清洗
规则
处理
时长 < 20 分钟
视为误触，不计入统计
时长 > 16 小时
视为忘记点「我醒了」，交由页面确认后处理
同一夜多条记录
保留时长最长的一条
「同一夜」的定义
以凌晨 4 点为分界，跨零点的睡眠不被拆成两晚
隐私
所有数据通过 wx.setStorageSync 保存在用户设备本地。
无账号体系、无网络请求、无第三方 SDK。卸载小程序即清除全部数据。
数据挖掘方法
一、KMeans 聚类（产品内实时运行）
实现位置：utils/portrait.js —— 即用户看到的「夜相」
- 特征：入睡时间偏移（以 18:00 为原点，跨零点连续累加）、睡眠时长
- 标准化：两个特征量纲不同（偏移约 1–11 小时，时长约 6–13 小时），
先做 z-score，否则数值大的特征会主导欧氏距离，聚类退化成「按入睡时间排序」
- k 的确定：按样本量——n ≥ 12 取 3，n ≥ 6 取 2，否则取 1
- 初始化：以首条记录为起点做最远点采样，全程不使用随机数，
同一份数据每次运行结果完全一致，可复现
- 类型映射：按主导簇的均值特征，用规则映射到六种类型
- 规律度：clamp(round(100 − 入睡标准差 / 180 × 100), 5, 99)
为什么不做分类：个人睡眠没有客观标签（「好睡眠」因人而异），
不适合有监督分类。无监督聚类是探索性的，更诚实。
二、关联分析（Apriori，离线脚本）
实现位置：analysis/association.py
- 离散化
  字段
  取值
  星期
  周一 ~ 周日（按凌晨 4 点归属）
  入睡时段
  早 < 22:00 / 正常 22:00–00:00 / 晚 ≥ 00:00
  睡眠时长
  短 < 7h / 中 7–10h / 长 > 10h
  晚睡原因
  用户选择项
- 事务：一晚的全部离散标签为一个事务
- 指标：支持度（常不常见）、置信度（准不准）、提升度（是否正相关）
运行方式：
cd analysis
python3 association.py sleep_data.json

技术难点与解决
问题
原因
解决
canvas 遮住界面文字
canvas 是原生组件，层级永远高于 WXML

每周周报评语相同

改用「第几天」做随机种子（每周 +7，天然轮转）

分段曲线的控制点不连续

只看「有无未关闭记录」
增加 isNightBed() 门控，白天小睡不计入晚睡
